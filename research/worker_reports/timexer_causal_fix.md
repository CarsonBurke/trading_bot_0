## 1. Validity flags scaled by 1/σ_k (features.rs / model.rs)
`FeatureSet::channel_mask` now takes `fn(Feature, usize) -> bool` and evaluates the role per channel. `Feature::sigma_scaled(self, channel)` is true only for channel 0 (the return value) of market/SPY; the validity flag (channel 1) is unscaled. `Feature::known_future(self, _channel)` stays per-feature on purpose: both channels of time-of-day (sin/cos), day-of-week (sin/cos), and session-gap (flag, ln(delta/5)) are legitimately known for future bars. Test `features.rs` `sigma_scaled` mask expectation updated to `[.., true, false, true, false]`; the model reads the mask unchanged (`sigma_scale`/`unit_scale` vectors), so market/SPY validity now enters tokens as 0/1 instead of ~500–10000.

## 2. mlq job 5040: `CUDA error: device-side assert triggered` in `copy_`
Diagnosis: not an index bug. The only device-side assert in this path is `check_objective` (`torch._assert_async(isfinite(loss))`, single_ticker_timexer/runner.rs:162), which fires asynchronously when the training NLL is nonfinite and then surfaces at the next synchronising `copy_` (H2D of the next batch / Muon `set_lr` host→device copy in `apply_schedule`). Audited every index-producing op at real shapes (unfold: `(6176-192)/16+1 = 375` windows starting at bar `t_k+1`; `known_index` < 12; RoPE table 375 = positions; reshapes `6000 = 375·16`) — all consistent.
CPU reproduction at real shapes (B=2, seq 6000, pred 192, patch 16, features all, 8×512 model, plain Adam lr 0.008 so no graph-capture check; throwaway test, deleted): step-0 NLL 3.18 → 32.1 → 4.9 → 83.6 → 9.4 → 10.0 → 14.9 → 600 → 1.4e18 → 8.4e6 → **inf** at step 10 with `log_scale ∈ [−125, 257]`, coordinates up to 318 → `RuntimeError: nonfinite TimeXer training objective` at step 11. Root cause: the head output layer is zero-initialised with fan-in 1024 and trained by AdamW at lr 0.008; Adam moves every weight by ≈lr per step, so a coherent first step shifts each output by O(lr·fan_in·E|h|) ≈ 8 (observed: log_scale min −3.6/max 7.1, coord 11.7 after ONE step). `exp(−log_scale)²` then overflows fp32 within a few oscillations. On the GPU with B=256 and real heavy-tailed targets this happened at the step after the optimizer graph capture (step 4–5).
Fix (model.rs): μP-style output multiplier `HEAD_OUTPUT_SCALE = 1/√1024` on the zero-init head output, and a tanh soft cap `LOG_SCALE_CAP = 4` on the log-scale around the `½·ln h` prior (`s/σ√h ∈ [e⁻⁴, e⁴]`), which bounds the NLL for any target. Zero weights still give exactly the persistence candle with `s = √h` (tanh(0)=0), so the persistence unit test and init NLL == baseline hold unchanged. Same repro after the fix: NLL 2.59, 6.02, 2.61, 2.65, 2.63, 2.59, 2.60, 2.58, 2.61, 2.64, 3.03, 2.58 (init baseline 2.5996 on this synthetic data); `log_scale ∈ [−1.9, 4.4]`, coordinates ≤ 3.3 across 12 steps. The PolarExpress engine ran its 3 warmup steps on CPU without error.
